# 0132 — CORS: configured origins, bearer tokens without credentials, and what a browser may read

## Status

**Accepted — filed unaccepted by milestone Client and integration of #93,
2026-10-13** (ADR 0066). Acceptance is the maintainer's act on the pull
request. Decided by the maintainer on the Client and integration plan:
- `Access-Control-Allow-Credentials` is never sent;
- a preflight is cacheable for a configured time;
- after Commit path (#91), `Varve-If-Graphs-Match` joins the allowed request
  headers.

## Context

A browser application, the Web UI milestone's first among them, calls the API
from another origin. Without CORS (Fetch Living Standard, §3.2) the browser
refuses to send anything but a simple request, and refuses to show the
response. The API's requests are rarely simple: they carry `Authorization`,
`If-Match`, `Varve-As-Of` and `Accept: text/event-stream`. Its responses carry
what a client needs in headers that are not CORS-safelisted: `Varve-Position`,
`ETag`, `Link`, `Location`, `Retry-After`, `WWW-Authenticate`.

Authentication is a bearer token in `Authorization` (ADR 0037), not a cookie.
Credentials mode, cookies and the TLS client certificate, is therefore never
needed. Allowing it would be the one CORS setting that turns a configuration
mistake into a cross-site request forgery.

## Decision

1. **`Varve:Cors:AllowedOrigins`**, a list of origins.
   - **The form of an origin:** scheme, host and optional port, with no path
     and no trailing slash. `*` is allowed and means any origin.
   - **The default is none.** With none configured, the CORS middleware is not
     added at all: no response carries an `Access-Control-*` header, and a
     preflight is an ordinary `OPTIONS` that the routes refuse (`405`, ADR
     0119).
   - **A malformed origin is refused at start**, as an unknown key is (ADR
     0115).
2. **`Access-Control-Allow-Credentials` is never sent.** Not configurable. A
   browser application sends its token in `Authorization`, which needs no
   credentials mode.
3. **Allowed methods:** `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`.
4. **Allowed request headers**, listed one by one, since CORS has no prefix
   wildcard:
   - `Authorization`, `Content-Type`, `Accept`;
   - `If-Match`, `If-None-Match`;
   - `Last-Event-ID`;
   - `Varve-As-Of`;
   - `traceparent`, `tracestate` (W3C Trace Context, ADR 0094's amendment).

   Commit path's `Varve-If-Graphs-Match` (ADR 0126) joins the list when that
   milestone's code is merged.
5. **Exposed response headers:**
   - `Varve-Position`, `ETag`, `Varve-Request-Id`;
   - `Link`, `Location`, `Retry-After`;
   - `WWW-Authenticate`.

   `Content-Type`, `Last-Modified` and `Cache-Control` are safelisted already.
   The `Varve-Error` trailer is not a header, and browsers do not expose
   trailers.
6. **`Varve:Cors:MaxAge`**, default ten minutes, is the preflight's
   `Access-Control-Max-Age`. Browsers cap it (two hours in Chromium), and the
   default stays under every cap.
7. **The middleware runs first**, after forwarded headers and before rate
   limiting, so:
   - a preflight is answered without a token and without spending a rate
     limit;
   - every response, a `401` or a `429` included, carries the CORS headers
     that let the browser show the problem body (ADR 0119) to the
     application that asked.
8. **Configured in the server, not the protocol package.** CORS is a host's
   policy about who may embed it. `Varve.Protocol` serves on any host
   (ADR 0091), and that host decides its own.

## Alternatives considered

- **Allow every origin by default.** The API needs a bearer token anyway, so
  the exposure is small. But an operator who never asked for browser access
  should not find it enabled. The Web UI's roadmap entry also serves it from
  the server's own origin, which needs no CORS.
- **Credentials mode for a cookie session.** No cookie exists to carry. Adding
  one for a UI would be a second credential scheme, which ADR 0037 refuses.
- **`Access-Control-Allow-Headers: *`.** Browsers exclude `Authorization` from
  the wildcard, so it would still need listing. A list states what the API
  reads.

## Consequences

- The Web UI's prerequisite "CORS in the server" is met by this milestone, and
  the roadmap says so.
- The protocol tests send browser-origin requests with and without a
  configured origin, and preflights, and assert no `Access-Control-*` header
  when unconfigured.
