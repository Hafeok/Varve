# 0033 — Commit traceability and AI-session records

## Status

Accepted. 2026-09-22.

Supersedes the wording rule from the milestone 3a close-out, which required
documentation prose to describe the project as AI-assisted without naming a
product. That rule is not abolished — it is narrowed to prose, and reversed for
the records.

## Context

The Mind Over Machine stewardship standard asks for one thing under this
heading, and it has two halves:

> **Full Traceability:** All commits on `main` are tied to tracked issues, and
> all generative AI chats/results utilized in development are fully documented
> and tied to issues.

Varve satisfies neither half today. There were no issues at all before this
adoption — the repository had three pull requests and nothing else — and the AI
assistance is recorded only as a `Co-Authored-By` trailer and a session URL that
resolves for one person.

The second half is the one that matters more here, because of how this
repository was actually built. Substantially all of Varve's code and every one
of its thirty ADRs were produced in AI-assisted sessions under the maintainer's
direction. The reasoning behind a decision is therefore split: the ADR records
the conclusion and the alternatives, and a transcript somewhere records how the
conclusion was reached, what was tried, and what was rejected before anything
was written down. A project that keeps only the first half is one where nobody
can later ask why the losing option lost, beyond what the winner chose to write.

There is a tension to resolve. The earlier wording rule said documentation
should name no product, and there were good reasons for it: a README that
advertises a vendor dates quickly, reads as endorsement, and tells a reader
nothing they need. But the standard requires the AI work to be *documented*, and
a record that will not say which tool and which model produced a result is not a
record — a session with "an AI assistant" in it cannot be reproduced, audited,
or weighed for known failure modes two years from now.

## Decision

### Every commit on `main` references a tracked issue

`Refs #N` for a commit that contributes to an issue, `Closes #N` for one that
completes it, in the commit **body**. Enforced by `eng/issue-refs.cs`, which
runs in CI over the commits a push or pull request adds and fails when one
carries neither.

**Merge commits are exempt**, by parent count. A merge's message is generated by
GitHub and describes the merge, not the work; the commits it brings are each
checked on their own. A merge whose body *does* carry a reference is fine and
this repository's merges will.

**Commits authored by a closed list of bots are exempt**, and this one is a
concession rather than a principle. Dependabot composes its own commit message
and offers no setting that would add `Refs #N` to the body, so the choice is
between exempting it and refusing automated dependency updates — which ADR
0009's amendment of the same date has just made a normal part of how this
repository is maintained. The pull request Dependabot opens is the tracking
artefact for those commits. The list is `dependabot[bot]` and
`github-actions[bot]`, it is in the gate's source rather than in configuration,
and widening it is how this gate would stop meaning anything.

### AI-assisted work is documented in `docs/traceability/`

One Markdown file per AI-assisted session, named `YYYY-MM-DD-issue-N-<slug>.md`,
containing:

- the **prompt** the session was given,
- the **tool and model** used, named exactly,
- the **report** the session returned,
- the issue it belongs to.

Sessions before this decision are **backfilled** as far as git history and the
pull request bodies allow, and each backfilled record says plainly what was
reconstructed rather than recorded.

**Design conversations that happened outside this repository** — the
specification, and the positions the ADRs settled — are recorded as one summary
file per topic, naming the decisions it produced, with a note that the
transcript is held by the maintainer. The maintainer attaches the transcripts.
A summary naming decisions is worth more than nothing and is honest about being
less than a transcript; claiming a record exists when it does not would be
worse than either.

### The wording rule splits

- **Prose** — `README.md`, `CONTRIBUTING.md`, `GOVERNANCE.md` and the
  documentation — describes the project as *developed with AI assistance under
  human review*, and **names no product**. This is unchanged.
- **Traceability records and issues name the tool and the model**, because the
  standard requires it and because a record that omits them does not do the job
  a record is for.

The distinction is between a claim about the project and a fact about a piece of
work. The first ages badly and belongs in no README; the second is evidence.

### The agent instruction file becomes vendor-neutral

`CLAUDE.md` is named after one product and is the file this repository's rules
actually live in. The rules move to **`AGENTS.md`**, which is vendor-neutral and
is the convention agents converging on the problem already read. `CLAUDE.md`
becomes a single line pointing at it, so the tool that looks for it still finds
the rules.

## Alternatives considered

- **Trust the commit message and check nothing.** Rejected on the repository's
  own standing rule: a rule that exists only in a document is not a rule. The
  cost of the check is a few seconds of CI and a script; the cost of not having
  it is that the first untraceable commit is discovered when someone needs it.
- **Tie pull requests to issues instead of commits.** Cheaper, and GitHub
  supports it natively. Rejected because ADR 0032 makes pull requests optional:
  a rule that only binds the pull-request path would leave the direct-push path
  — now a first-class route — entirely untraced. The two decisions have to be
  taken together or the standard is met on paper only.
- **Allow `Fixes`, `Resolves` and a bare `#N`.** Rejected in favour of exactly
  two forms. `Refs` and `Closes` say different things and the difference is
  worth keeping; a bare `#N` appears in prose by accident often enough
  ("as #12 describes") that accepting it would make the gate pass on commits
  that reference nothing deliberately.
- **Record AI sessions in the commit trailer only**, as the repository does
  today. Rejected: a trailer holds a URL that resolves for one person and
  nothing else. It records *that* a session happened, which is the least useful
  fact about it.
- **Publish the transcripts in the repository.** Attractive, and the fullest
  possible reading of the standard. Not decided here: transcripts are long,
  contain the maintainer's unedited working, and cannot be redacted
  retroactively once pushed. The summary-plus-held-transcript arrangement is
  what is adopted now; publishing them remains open and would need no
  superseding ADR, only a decision to do it.
- **Keep `CLAUDE.md` and add `AGENTS.md` beside it.** Rejected: two files
  holding the same rules diverge, and the one that diverges is the one nobody
  edited. The pointer keeps both entry points with one source.

## Consequences

- **`eng/issue-refs.cs` is a new gate**, proven by a failing run before it is
  trusted, like every other gate here.
- **An issue must exist before the work does.** For this adoption that meant
  creating eighteen issues first — one per milestone, one per ADR set, one for
  the adoption itself — and backfilling the four that were already complete.
  The ordering is a real constraint on every future change and is the point.
- **The backfill is incomplete by construction.** Milestones 1 and 2 predate
  every mechanism that would have recorded them; their records are
  reconstructions from git history and say so. Nothing can fix that
  retroactively, and pretending otherwise would defeat the purpose.
- **`docs/traceability/` grows with every session.** That is the cost, and it is
  the same cost as the ADR directory, which has been worth paying.
- **This ADR does not make AI-assisted work special.** It makes it *recorded*.
  The gates, the ratchet and the review apply identically whoever or whatever
  produced the diff, which is the foundation's position: AI agents work
  alongside developers under the same strict quality standards.
